# scripts

| 文件 | 用途 |
|---|---|
| `verify.sh` | 面评发布门禁：校验报告完整性与内容合规，退出码非 0 时调度脚本告警 |
| `chrome-eval.sh` / `chrome-eval.jxa.js` | 在已登录的 Chrome 标签页里执行 JS（采集飞书招聘页面用） |
| `multi-review.sh` | 发布门禁：3 模型 × 2 侧重共 6 路独立复核，退出码 1 = 有高危 findings |
| `pdf2png.swift` | 简历 PDF 转长图 |

> `verify.sh` 与 `multi-review.sh` 各有一份运行副本在 `~/hire_patrol/`，改动后两边要保持同步。

## macOS 上不存在的两个命令（都踩过，且失败是静默的）

| 命令 | 后果 |
|---|---|
| `setsid` | 用来脱离终端会导致整批 review 静默不启动。改用 `nohup ... </dev/null &`（脚本里已按此写） |
| `timeout` | **2026-09-11 踩到**：`timeout 3000 ./multi-review.sh ...` 直接 `command not found`，但外层管道的退出码是 **0**——看起来像"review 跑完且无高危"，实际一路都没启动。手工调 review 时直接 `bash multi-review.sh <目录>`，脚本内部已有 40 分钟硬超时与多数完成宽限，不需要外部 timeout |

> 共同点：两个命令都来自 GNU coreutils，Linux 上习惯成自然，macOS 默认没有。**失败形态都是"静默 + 退出码正常"**，比报错更危险。

## 陈旧 review 文件会被当成本次结论（已加自动归档）

`multi-review.sh` 判定"某路是否产出"用的是**文件非空**（`[[ -s "$REVIEW_DIR/${l}.md" ]]`），不看 mtime。所以目录里若残留上一版报告的 review 文件，等待循环会立刻判定已达多数、6 分钟宽限后杀掉正在跑的进程，并把**旧结论**汇总进 `SUMMARY.md`——看起来 review 过了，实际复核的是旧报告。

2026-09-11 用新规则重写两份旧五维报告时踩到：目录里有 4 份前一天的 review 文件。

脚本现在会自动检测并归档：任一 `*-pass*.md` 比 `evaluation.md` 更旧，就说明报告在上次 review 之后被重写过，整批 review 作废，移到 `review-stale-<evaluation.md 的 mtime>/`。

## verify.sh

```bash
./verify.sh <targets 清单文件> [patrol 退出码]
INTERVIEWS_ROOT=/path/to/interviews ./verify.sh targets.txt   # 覆盖材料根目录
```

`targets` 清单每行一个候选人轮次目录的绝对路径。退出码 `0` = 全部通过，`1` = 有缺失或门禁未过。

### 为什么需要它

**LLM 自查查不出自己的系统性偏差。** 这个脚本把能确定性判定的规则做成 shell 校验，不依赖模型是否记得自查。每一条检查都对应一次真实事故：

| 检查 | 事故 |
|---|---|
| 报告文件存在且非空 | 2026-08-18 `claude -p` 在评估子代理跑完前就退出，采集完成但报告没写出来，调度脚本记 `exit=0`，无人发现 |
| 空清单 + patrol 异常退出 → 判失败 | 2026-09-07 采集进程崩溃导致清单为空，旧逻辑判成"今日无未评价面试"正常退出，**把失败伪装成没活干** |
| 非法路径计入 missing | 同一模式的隐藏变体：清单被写错时只打 `[SKIP]` 就跳过、退出码仍是 0 |
| 分数档位白名单 | 2026-09-08 出现档位外的分数 |
| 禁"正负相抵"类表述 | 2026-09-08 自创规则外的抵消算法，导致判分倒挂——交付错误代码的候选人分数**高于**零输出的候选人 |
| 面试官档位禁子档 | 2026-09-08 连续三份用 `A-`/`B+`/`B-` 等未定义档位，三者互不可比 |
| 维度表必须含「编码与算法」 | 2026-09-08 规则改六维后，三份报告仍用五维表头把编码结果塞回技术深度 |
| 禁内部术语与断链引用 | 对外交付物混入 `coding-analysis.md` 这类招聘系统里点不开的引用，以及内部评分术语 |
| 禁自造标题 / 禁复述简历 | 2026-09-09 报告末尾自造「资格信息」表复述学历届次岗位，用户指出"简历都有，面评只需要保留简历没有的内容" |
| 引语回本人材料溯源 | 2026-09-09 **跨候选人证据污染**：把 A 的项目数据"三万多条"写进了 B 的报告，还当成判定依据。并行评估多人时上下文同时装着多份材料，串台是系统性风险 |
| 旁听场不得给用户打档 | 2026-09-10 `chenzhenran/002` 是涂鹏主面、用户 shadow 陪面（用户全程零发言）。复盘开篇正确交代了"复盘对象是涂鹏"，**却仍在评分栏写了 `C`**——那个档评的是涂鹏，出现在用户的自我复盘里就是评错了人。飞书 `interviewer_list` 只登记 shadow 者一人，系统字段判不出主面 |

### 旁听场档位检查的实现要点

复盘正文自述本场为 `shadow` / `陪面` / `旁听` 时，评分栏必须写「不评档」，出现 A/B/C/D 即拦下。

- **为什么用正文自述做触发条件**：脚本拿不到"谁是主面"这个事实（飞书只登记 shadow 者一人），但写报告的模型知道，且按模板必须在开篇交代归属。所以门禁校验的是**自述与档位的一致性**——既然你写了这是陪面场，就不能同时给用户打档。
- 正则末尾排除 `[+-]` 与字母，避免与上一条"禁子档"检查重复报错，也避免把「不评档」里的字误判成档位。

### 引语溯源的实现要点

抽出报告里**含数字**的引号短语，去掉所有空白后回本人 `asr.md` 比对：

- **只查含数字的**：纯文字引语在 ASR 清洗后往往找不到，误报率过高；数字型引语最容易串台，也最容易核实。
- **两侧去空白**：报告排版会给中英文数字加空格（`"100 多个"`），而 ASR 原文是 `"100多个"`，直接 grep 会全量误报。
- **简历兜底**：简历引语是合法来源，但简历多为 PDF/PNG 无法 grep，所以若该引语所在行显式写了「简历」，视为已交代出处并放行。
